# CraftPilot 0.16.0-alpha

One combined update: includes the QuestieDB packaged-Forever detection and First Aid owned-profession fixes, plus the following features.

- Cached AH unit price, scan age, net AH unit proceeds using the configured deduction, and separate vendor sale value beside recipe results and materials throughout the existing views and cost window. Missing data and non-item outputs stay unknown; unit proceeds never silently fund material purchases.
- Keep/sell advice: protect explicit plan requirements, identify other learned uses and possible reference follow-up recipes, otherwise compare fresh AH net with vendor sale. Bind-on-pickup/quest items and incomplete/stale prices cannot receive a false AH sale recommendation. Follow-up hints do not invent demand quantities or promise recipe availability.
- Ingredient stock directly at recipe rows with compact Bags/Bank counts and full per-item hover details. Material/cost views include explicit stock and reservations; row heights adapt to additional text.
- Auctionator shopping-list button in profession and camping plans. Exact item names and missing quantities are passed through the public ConvertToSearchString/CreateShoppingList API. Skill ranges use the selected automatic route or explicit manual steps. An empty plan can build the selected range automatically. Other list names are untouched; matching CraftPilot lists are refreshed or cleared when no shortages remain.
- Manual plans now resolve selected producer/consumer dependencies using captured minimum output quantities, preventing planned intermediates from being bought a second time. Costs and material views use the same external material requirements. Missing output/material data, cycles, ambiguous names and incomplete automatic routes stop export before writing a partial list. Open profession windows once to capture output quantities.

Validation: full Lua suite, actual reported QuestieDB Baked/contract-4/Forever metadata shape and First Aid 129 at 35/75; green ownership marker; AH versus purchase/vendor-price separation; net cuts, unknown/stale/bound safeguards; explicit keep quantities and reference hints; native output handling; exact Auctionator quantities, owned/produced intermediates, other-plan reservations, zero-shortage list clearing and preflight failures; bilingual views and reproducible install archive. The Auctionator public API signature was inspected in the official packaged addon; no third-party implementation or new dataset is bundled. In-game creation/search and rendering are not claimed as independently observed by the automated suite.

Prices and skill routes remain estimates. Vendor sale is not vendor purchase; all market values are per item. Bind state, personal use, demand, travel and unsuccessful auction deposits can affect a sale decision. Manual plans export only explicitly selected steps. Reservations are a planning aid, not an inventory lock. Auctionator handles its own list/search UI; purchases remain manual.
